# Paper X-Ray

在 PDF 论文之上外挂一层可插拔的标注。多个可自定义的 lens（agent）各盯一个方面，自动定位并批注原文；人类在同一份文档上标注、回复，组织内实时共享。

定位是**便于 agent 集成与多人协作的 PDF 论文阅读架构**，不是又一个阅读器产品。

## 技术栈

- 前端：React + TypeScript + Vite，`pdfjs-dist` 渲染
- 后端：Node.js
- 数据库：MariaDB
- 渲染层：可直接用 `react-pdf-highlighter` 系列或自写覆盖层，**不要重复造高亮渲染的轮子**

## 实现顺序

**第一步不是写页面，是把三份契约定死**，写成 TypeScript 类型 + 文档：

1. **IR**：`Document` / `Node` / `CharMap`
2. **Annotation**：`HumanAnnotation` 与 `AgentAnnotation` 两类，生命周期不同
3. **LensSpec**：lens 的声明格式

定义见 `docs/01-nabcd-architecture.md` 的「核心数据模型」。三份定下来，四个模块才能并行。

第二步是打通一条最小垂直切片：上传 PDF → 解析 → 一个写死结果的假 lens → 标注显示在侧栏列表。**先不做高亮渲染**，侧栏能显示就算通。

## 几条不能违反的约束

- **PDF 文件永不修改。** 标注外挂存储，通过覆盖层渲染。`contentHash` 即文档 ID
- **agent 标注不可变。** 要改就整批重跑生成新 run，不做原地更新。人类标注可改可删
- **每条 agent 标注必须带 `evidenceSpan`，服务端必须独立复核。** 不信任客户端的校验结果
- **用户的 API key 绝不进服务端、绝不进数据库。** 个人 lens 在浏览器执行
- **不做 CRDT / OT。** 服务端做真值源 + WebSocket 广播；人类侧并发用乐观锁（每条带 `version`，冲突则拒绝并返回当前值）
- **URL 导入必须做 SSRF 防护。** 域名白名单 + 拒绝内网地址段

## 关键难点提示

**CharMap 是整个项目的枢纽**：归一化全文的字符区间 ↔ 哪些 `text item` 的哪几个字符。上层锚定和下层渲染都依赖它。写对了两边都通，写错了到处是难查的 bug。优先把它的单元测试写扎实。

**反向映射没有现成库**：现有高亮库解决的是「用户选中 → 存下来」（正向），本项目需要「系统算出一段文本 → 定位到矩形」（反向）。这部分必须自己写。

**渲染降级链**：精确多矩形 → 整段块 → 页边标记 → 侧栏列表。哪一级算不出就退到下一级，不要崩。降级行为本身要写测试。

**防刷屏**：多个 lens 同时跑，一篇论文可能标出上百条。默认只显示高置信度、按 lens 分组开关、页边密度条、每个 lens 限量。这个不要留到最后做。
