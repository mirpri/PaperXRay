# 讨论中的 AI 回复

每条标注和回复的操作栏中，Reply 旁提供“Reply with AI”。Provider / Model 与 Lens 设置共用选择组件，支持组织和个人 Provider；模型建议列表不限制手动输入。浏览器按用户记住上次选择，不保存或上传额外密钥。产品界面使用英文。

不提供额外问题输入框：AI 直接回应当前评论，并作为其子回复保存。要提问或追问时，先使用普通 Reply 发布评论，再对该评论使用 Reply with AI。AI 答案明确标注 AI、模型和 Provider，普通用户不能编辑为人类评论；发起者和有权限的管理员可删除。

上下文由服务器根据当前访问权限构建，只包括当前祖先讨论分支、标注原文、邻近原文和论文前 90000 个 Unicode 字符。论文较长时会截断全文，但标注附近文本仍单独提供。AI 被要求使用问题语言、以论文为依据、缺乏依据时说明，不编造出处。没有浏览器或外部检索工具。

组织 Provider 在服务端后台执行，响应立即返回新回复；个人 Provider 由浏览器直接调用，服务器只接收答案，API key 始终留在浏览器。组织执行可以跨刷新继续；个人执行需要页面保持打开，浏览器中断后会超时标记失败。

`ai_replies` 只存模型选择、回复关联和状态，不存论文全文、Prompt 或 API key。启动时自动创建该表，当前完整 schema 也包含它。同一个用户对同一父评论的未完成请求会复用。状态随原标注查询返回；Socket 通知立即刷新，存在进行中的回复时每 2.5 秒轮询兜底。

模型请求上限 8 分钟。组织 worker 每 30 秒续租、租约 90 秒；个人调用最多等待 9 分钟接收结果。过期结果不覆盖当前状态。失败答案保留为明确的失败状态，可删除或重新向原评论请求回复。
